## 1. 产品概述

### 1.1 产品名称
**PandaMart PMS** (Panda Mart Product Management System) — 熊猫超市智能库存管理系统

### 1.2 产品愿景
为熊猫超市（综合亚洲超市）提供一站式**LLM驱动的智能库存管理解决方案**。系统深度集成大语言模型（LLM），通过AI视觉识别自动化发票入库，通过自然语言对话提供智能库存分析、订货建议、经营洞察等决策支持。支持多AI提供商（OpenAI兼容接口 / 阿里千问 Qwen），用户可自定义 Base URL、API Key、模型名称，灵活切换。大幅降低人工录入成本和运营管理难度。

### 1.3 目标用户
| 角色 | 描述 | 典型场景 |
|------|------|----------|
| **管理员 (Admin)** | 超市老板/经理 | 查看分析报表、审批订货、管理供应商、系统配置 |
| **店员 (Staff)** | 一线店员 | 上传发票、确认入库、查看库存、提交订货申请 |

### 1.4 业务背景
- **超市类型**：综合亚洲超市，经营干货、蔬果、冷冻、调味料、饮料、日用品等全品类
- **运营规模**：单店运营，15-50个供应商，每周处理30-100张发票
- **发票特征**：中英文双语产品名称，单位多为 Case/Box/Bag 等批发单位
- **当前痛点**：手动录入发票耗时易错、库存盘点依赖人工、缺乏数据分析支撑决策

## 2. 核心功能模块

### 2.1 智能发票识别 (Invoice OCR)

#### 2.1.1 功能描述
系统支持多种格式的发票文件上传，自动识别并结构化提取发票中的关键信息。

#### 2.1.2 支持的输入格式
| 格式 | 处理方式 | 说明 |
|------|----------|------|
| **PDF（文本型）** | 直接文本提取 | 使用 pdf-parse 库提取文本后模板匹配 |
| **PDF（扫描型）** | AI 视觉识别 | 检测到无可提取文本时，转为图片后调用 LLM Vision |
| **图片 (JPG/PNG)** | AI 视觉识别 | 手机拍照/扫描件，调用 LLM Vision API（支持多提供商） |
| **Excel (XLSX/XLS)** | 直接解析 | 使用 xlsx 库解析表格数据 |

#### 2.1.3 提取字段
| 字段 | 英文名 | 说明 | 必填 |
|------|--------|------|------|
| 供应商名称 | supplier_name | 发票上的供应商公司名 | ✅ |
| 供应商编号 | supplier_code | 如有 | ❌ |
| 发票编号 | invoice_number | 发票唯一编号 | ✅ |
| 发票日期 | invoice_date | 发票开具日期 | ✅ |
| 客户编号 | customer_code | 超市在供应商处的编号 | ❌ |
| 产品英文名 | product_name_en | 商品英文名称 | ✅ |
| 产品中文名 | product_name_zh | 商品中文名称 | ❌ |
| 数量 | quantity | 购买数量 | ✅ |
| 单位 | unit | Case/Box/Bag/Lb 等 | ✅ |
| 单价 | unit_price | 每单位价格 | ✅ |
| 行小计 | line_total | 该行总价 (quantity × unit_price) | ✅ |
| 税前小计 | subtotal | 所有行的合计 | ✅ |
| 是否含税 | has_tax | 发票是否有税 | ✅ |
| 税率/税额 | tax_amount | 税总金额 | ❌ |
| 税后总价 | grand_total | 含税总价 | ✅ |

#### 2.1.4 用户操作流程
1. **上传文件**：用户通过拖拽或选择文件上传发票（支持手机拍照）
2. **自动识别**：系统自动检测文件类型并执行相应的解析/OCR
3. **结果预览**：以表格形式展示识别结果，高亮低置信度字段
4. **人工校对**：用户可编辑修正任何字段，支持原图/PDF 对照查看
5. **确认入库**：校对完成后确认，数据写入库存系统

> 权限边界说明：店员可在“当前待处理发票”的收货校对流程中查看该张发票的金额、单价、小计和总价，以便完成校对与确认入库；但店员不可查看历史采购金额、价格趋势、供应商累计采购金额或其他脱离当前收货流程的财务数据。

#### 2.1.5 智能学习
- **供应商模板记忆**：同一供应商的发票格式通常固定，系统记忆模板提高后续识别速度
- **产品名称智能匹配**：根据已有产品库，自动匹配已知产品，避免重复录入
- **历史价格对比**：识别后自动与上次采购价对比，价格异常时高亮提醒

### 2.2 库存管理 (Inventory Management)

#### 2.2.1 产品管理
- **产品信息**：中英文名称、SKU编码、条形码、分类、供应商、默认单位、默认进价（默认进价仅管理员可见）
- **分类体系**：支持多级分类（如：蔬菜 > 叶菜类 > 菠菜）
- **产品图片**：可上传产品图片
- **批量操作**：支持批量导入/导出产品信息（Excel格式）

#### 2.2.2 入库管理
- **发票入库**：通过发票识别自动入库（主要方式）
- **手动入库**：支持手动录入入库信息
- **入库审核**：可配置是否需要管理员审批
- **入库记录**：完整的入库历史记录，支持按日期、供应商、产品筛选

#### 2.2.3 库存盘点
- **当前库存查询**：实时显示各产品当前库存量
- **库存预警**：低于安全库存时自动告警（站内通知 + 可选邮件通知）
- **盘点功能**：支持定期盘点，自动计算盈亏差异
- **库存调整**：支持手动调整库存（报损、赠品、内部消耗等），需填写原因

#### 2.2.4 出库管理
- **手动出库**：记录报损、退货、内部使用等出库行为
- **出库记录**：完整的出库历史追踪

### 2.3 智能数据分析 (Analytics)

#### 2.3.1 仪表盘 (Dashboard)
- **今日概览**：今日入库/出库金额、待处理发票数、库存预警数
- **本周/月趋势**：入库金额趋势图、采购频次统计
- **供应商分析**：各供应商采购占比饼图
- **分类分析**：各品类采购金额/数量占比

#### 2.3.2 畅销/滞销分析
- **畅销产品 Top N**：按采购频次/数量排名，反映动销情况
- **滞销产品预警**：长时间未采购的产品提醒（可能缺货或已停售）
- **采购趋势**：单品采购量的时间趋势，识别季节性波动
- **新品/停售提示**：检测到新出现的产品或长期未出现的产品时提示

#### 2.3.3 价格分析
- **价格波动追踪**：追踪每个产品的历史进价变动
- **涨价提醒**：价格异常上涨时自动告警
- **供应商价格对比**：同一产品在不同供应商处的价格对比
- **成本趋势**：总体采购成本月度趋势

#### 2.3.4 智能订货建议
- **安全库存计算**：根据历史销售数据自动计算建议安全库存
- **自动订货提醒**：库存低于安全线时推荐订货量
- **采购周期分析**：分析各产品的采购周期规律
- **预算估算**：根据建议订货量估算采购预算

### 2.4 LLM 智能助手 (AI Assistant)

#### 2.4.1 功能描述
系统深度集成 LLM，提供超越传统库存系统的智能化体验。所有 AI 功能统一通过 **OpenAI 兼容接口** 调用，支持多种 AI 提供商。

#### 2.4.2 多 AI 提供商支持
| 提供商 | 接口协议 | 说明 |
|--------|----------|------|
| **自定义 OpenAI 兼容** | OpenAI API | 支持自定义 Base URL、API Key、模型名，可接入任何兼容接口（如本地部署、第三方中转） |
| **阿里千问 (Qwen)** | OpenAI 兼容 | 通义千问系列模型，通过 DashScope 的 OpenAI 兼容端点调用 |
| **OpenAI 官方** | OpenAI API | GPT-4o / GPT-4o-mini 等官方模型 |

系统通过 Web UI 配置 AI 提供商参数，无需修改代码即可切换模型。

#### 2.4.3 AI 提供商配置参数
| 参数 | 说明 | 示例 |
|------|------|------|
| 提供商名称 | 显示名称 | "本地 GPT" / "千问" / "OpenAI" |
| Base URL | API 服务地址 | `http://127.0.0.1:8317` / `https://dashscope.aliyuncs.com/compatible-mode` |
| API Key | 认证密钥 | `sk-xxxxx` |
| 模型名称 | 使用的模型 | `gpt-5.2` / `qwen-vl-max` / `gpt-4o` |
| Thinking Effort | 思考深度 | `xhigh` / `high` / `medium` / `low`（可选，部分模型支持） |
| 是否支持 Vision | 是否支持图片输入 | 用于发票图片 OCR |
| 用途 | 该提供商用于哪些功能 | `ocr` / `analysis` / `chat` / `all` |
| 是否启用 | 是否激活 | 可同时配置多个，按用途选用 |

#### 2.4.4 智能化功能场景

**发票智能识别（LLM Vision）**
- 调用支持 Vision 的 LLM 直接识别发票图片/扫描件
- LLM 理解发票语义，而非简单 OCR 字符识别
- 自动处理复杂表格布局、中英文混排、手写注释

**智能对话分析（LLM Chat）**
- 用自然语言提问库存和采购相关问题
- 例："最近一个月哪些蔬菜涨价最多？" "CBS 上周送了什么货？" "帮我列一个本周需要订的货"
- LLM 自动查询数据库并生成人类可读的分析报告

**智能订货建议（LLM Analysis）**
- 基于历史采购数据，LLM 生成带分析推理的订货建议
- 考虑季节性、节假日、价格波动等因素
- 生成自然语言的订货理由说明

**产品智能匹配（LLM Matching）**
- OCR 识别的产品名与已有产品库的智能匹配
- 处理别名、缩写、中英文不一致等情况
- 例："NAPA" 自动匹配 "NAPA CABBAGE 绍菜"

**异常检测与洞察（LLM Insight）**
- 自动发现异常模式（突然涨价、采购量骤变等）
- 生成自然语言的异常说明和建议
- 周期性生成经营分析摘要

### 2.7 系统设置 (Settings)

## 3. 非功能性需求

### 3.1 性能要求
- 页面加载时间 < 2秒
- 发票 OCR 处理时间 < 15秒（AI识别）/ < 3秒（文本提取）
- 支持同时在线用户数 ≥ 10

### 3.2 安全要求
- 所有通信使用 HTTPS
- 密码 bcrypt 加密存储
- JWT Token 认证，Token 有效期 24 小时
- 防 SQL 注入、XSS 攻击
- API 限流保护
- 敏感操作记录审计日志

### 3.3 兼容性要求
- **桌面浏览器**：Chrome、Firefox、Safari、Edge 最新两个版本
- **移动端**：iOS Safari、Android Chrome，响应式适配
- **平板**：iPad、Android Tablet 横竖屏适配
- **最低屏幕宽度**：320px（iPhone SE）

### 3.4 可用性要求
- 中文界面为主，关键功能有英文对照
- 直觉化操作，减少培训成本
- 关键操作有确认提示
- 错误信息清晰友好

### 3.5 数据要求
- 数据库定期自动备份（利用Namecheap cPanel功能）
- 支持手动导出全量数据
- 发票原件（PDF/图片）保留至少2年

## 4. 用户故事

### 4.1 发票入库场景
> **作为** 店员，  
> **我希望** 用手机拍照发票后上传系统能自动识别所有产品信息，  
> **以便于** 我只需快速校对确认就能完成入库，而不用逐行手动录入。

### 4.2 库存预警场景
> **作为** 管理员，  
> **我希望** 系统在库存低于安全线时自动通知我，  
> **以便于** 我能及时联系供应商订货，避免缺货。

### 4.3 采购决策场景
> **作为** 管理员，  
> **我希望** 查看各品类的销售趋势和采购分析报表，  
> **以便于** 我能科学地规划订货量和控制成本。

### 4.4 价格监控场景
> **作为** 管理员，  
> **我希望** 系统自动追踪每个产品的进价变动并在异常涨价时告警，  
> **以便于** 我能及时与供应商沟通或寻找替代供应商。

### 4.5 手机操作场景
> **作为** 店员，  
> **我希望** 在手机上也能流畅地使用所有功能，  
> **以便于** 我在货架旁就能直接拍照上传和查看库存。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 共享主机性能限制 | AI调用延迟、并发受限 | AI调用异步处理，队列机制；考虑后期升级VPS |
| OCR/AI识别准确率不足 | 增加人工校对工作量 | 供应商模板记忆、持续优化提示词、人工纠错反馈 |
| 供应商发票格式差异大 | 模板匹配困难 | 优先AI识别，逐步积累模板库 |
| API调用费用 | 运营成本增加 | PDF文本提取优先（免费）；AI仅用于图片/扫描件 |
| 数据安全 | 客户/供应商数据泄露 | HTTPS、加密存储、权限隔离、定期备份 |
